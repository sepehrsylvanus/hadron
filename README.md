# Hadron — دو فضای مستقل

- **`main-erp/`**: تمام کار قبلی ERP، با همان .NET / EF Core / PostgreSQL / React. دستورهای قبلی را پس از `cd main-erp` اجرا کنید. لانچر ریشهٔ `run-hadron.bat` به لانچر داخل این پوشه ارجاع می‌دهد. نسخهٔ Node موردنیاز اپ فعلی در `main-erp/src/frontend/package.json` است (26.x).
- **`nx-erp-lab/`**: راهنمای فارسی آفلاین و دستور ساخت آزمایش مستقل Nx + NestJS + Prisma + PostgreSQL؛ React فقط پوستهٔ اولیه. این پوشه مهاجرت اپ فعلی به Nest نیست و هیچ اتصال/انتقال داده‌ای به دیتابیس فعلی ندارد.

## راهنما

فایل **[`nx-erp-lab/implementation-guide.html`](nx-erp-lab/implementation-guide.html)** را در مرورگر باز کنید. بستهٔ همراه شامل Schema محدود، منشأ تصمیم‌ها، فایل‌های قابل کپی و تست‌های نمونه است. قراردادهای API و مراحل ساخت دامنه در راهنما برنامهٔ پیاده‌سازی‌اند، نه ادعای پیاده‌سازی همهٔ سرویس‌ها.

انتخاب جداول در `nx-erp-lab/scope.json` صریح است: ۲۹ جدول دامنه و snapshotهای برنامه‌ریزی + ۱۳ جدول پشتیبان/مرجع؛ نه همهٔ ۱۸۰ جدول Data Map. وجود یک جدول پشتیبان به معنی مجوز ساخت کل ماژول آن نیست. مالی، فروش، گردش کامل انبار، سفارش خرید/تولید و مراحل آیندهٔ بازرگانی خارج از محدوده‌اند.

## دریافت امن

راهنمای کامل در [`docs/SAFE-UPDATE-FA.md`](docs/SAFE-UPDATE-FA.md) است. شاخهٔ تحویل: **`arena/d5f0785f-hadron`**. بدون PR و بدون force push.

اگر تغییر محلی دارید، یک clone تازه در پوشه‌ای دیگر کم‌ریسک‌ترین روش است. `pull --ff-only` فقط روی شاخهٔ صحیح و working tree تمیز؛ اگر تاریخچه واگرا باشد متوقف می‌شود، نه اینکه merge تعارض‌دار ایجاد کند. فایل‌های `.env` و داده‌های Docker جابه‌جا/حذف خودکار نشده‌اند؛ برای ادامهٔ اجرای ERP، تنظیمات محلی نادیده‌گرفته‌شده را با دقت به مسیر جدید `main-erp/` منتقل/کپی کنید. هرگز volume را برای این تفکیک حذف نکنید.
