# Hadron ERP — UI Brand Rules

## 1. Authority and Purpose

This document translates the official Hadron Tavan Brand Identity into practical rules for the Hadron ERP user interface.

The authoritative source is:

`docs/brand/Hadron-Brand-Guidelines.pdf`

The official Brand Guideline always has higher authority than this document.

This document contains two different types of rules:

### OFFICIAL BRAND RULE

A rule directly derived from the Hadron Brand Guideline.

### ERP UI INTERPRETATION

A software-specific implementation decision derived from the official brand principles.

Never present an ERP-specific design decision as if it were explicitly stated in the Brand Guideline.

---

- understandable

- without exaggeration

- professional

For enterprise software, the official brand personality translates into an interface that should feel:

- calm

- technical
- trustworthy

# 8. Color Usage in ERP

## ERP UI INTERPRETATION

Do not make the entire ERP red.

Hadron Red should function primarily as a controlled brand and emphasis color.

Suitable uses may include:

- selected navigation
- primary highlights
- important actions
- brand accents
- critical indicators where semantically appropriate

Large operational surfaces should generally remain:

- white
- neutral
- light gray
- low contrast

Secondary colors may be used as light status backgrounds.

Strong saturated colors should be used sparingly.

---

# 10. Persian Typeface

## OFFICIAL BRAND RULE

The official Persian typeface is:

`Vazir`

The Brand Guideline defines five weights:

- Thin
- Light
- Regular
- Medium
- Bold

Vazir was selected because of:

- readability
- appropriate proportions
- ability to clearly communicate information
- compatibility with different media
- suitability for websites

Use the official font assets supplied to the project.

Do not replace the Persian brand typeface without approval.

---

# 11. Persian Typography in ERP

## ERP UI INTERPRETATION

Recommended use:

### Regular

- body text
- input values
- data-grid values
- descriptions

### Medium

- labels
- navigation
- table headers
- secondary headings

### Bold

- page titles
- major headings
- important KPI values

### Light / Thin

Use selectively.

Do not compromise readability in dense operational interfaces.

Avoid unnecessary use of Bold.

---

# 12. English Typeface

## OFFICIAL BRAND RULE

The official English typeface is:

`MYRIAD PRO`

The Brand Guideline states that the family contains eleven weights.

Three approved weights are specifically used for Hadron:

- Regular
- SemiBold
- Bold

Use these approved weights when official licensed assets are available.

Do not download or redistribute unofficial font files.

# 13. Font Availability

## ERP UI INTERPRETATION

If an official font asset is not available or cannot legally be embedded:

- do not silently download an unofficial copy
- do not substitute it permanently without approval
- use a temporary technically appropriate fallback
- document the fallback
- request approval before making it permanent

# 15. Logo Asset Rules

## OFFICIAL BRAND RULE

Never:

- redraw the logo
- recreate it with text
- alter the logo proportions
- distort it
- arbitrarily recolor it
- modify its geometry
- add decorative effects
- use an unofficial approximation

Official frontend assets should be stored under:

`src/frontend/src/assets/brand/`

# 16. Official Logo Clear Space

## OFFICIAL BRAND RULE

The official Brand Guideline requires clear space around the Hadron logo.

No competing visual element should enter this protected area.

This includes:

- text
- icons
- borders
- images
- other logos

The exact proportions defined in the official Brand Guideline must be respected.

Do not approximate the official clear-space construction if a prepared logo asset or specification is available.

---

# 17. Official Minimum Logo Size

## OFFICIAL BRAND RULE

The Brand Guideline shows minimum-size requirements for the Hadron logo.

The examples indicate:

- approximately `3 cm` minimum for the logo configuration including the tagline
- approximately `1.5 cm` minimum for the simplified logo configuration

For digital interfaces, do not blindly convert these dimensions into arbitrary pixels.

Preserve equivalent legibility and proportions.

If a smaller digital use is required, obtain project-owner approval before creating a special small-format variant.

# 21. Pattern in ERP

## ERP UI INTERPRETATION

The official Pattern may be adapted very selectively for digital use.

- login background
- PDF/report covers

- data grids
- dense forms

# 22. Official Layout Principles

## OFFICIAL BRAND RULE

Hadron layout must communicate:

- intelligence
- order
- reliability
- control
- clarity
- confidence

The official layout rules include:

- maintain consistent visual rhythm horizontally and vertically
- use generous margins to increase readability
- avoid information congestion, especially in technical content
- create calmness, order and trust
- make titles clear, strong and distinguishable
- keep body text readable and organized
- present technical information in layers and step-by-step
- respect logo clear space
- respect brand typography
- respect brand colors
- respect the official Pattern

---

# 23. ERP Layout Interpretation

## ERP UI INTERPRETATION

Operational screens should translate the official Layout principles into:

- consistent spacing
- consistent alignment
- clear hierarchy
- controlled density
- predictable placement
- strong section organization

A typical operational page may follow:

```text
Page Header
↓
Context / Filters
↓
Summary when useful
↓
Primary Form / Grid / Workflow
↓
Supporting Information
```

This structure is an ERP interpretation, not an exact layout prescribed by the Brand Guideline.

---

# 24. Information Density

## OFFICIAL BRAND RULE

The Brand Guideline explicitly discourages excessive information density, particularly for technical information.

## ERP UI INTERPRETATION

ERP tables may necessarily contain significant information.

When density is unavoidable:

- preserve readable spacing
- group related information
- allow filters
- allow column control
- use progressive disclosure
- avoid displaying irrelevant columns by default

Dense does not mean visually chaotic.

- restrained icons
- obvious selected state

# 33. Data Grids

## ERP UI INTERPRETATION

Data Grids should reflect the official brand traits:

- precise
- ordered
- engineered
- controlled
- readable

- subtle separators
- restrained headers
- consistent alignment
- clear editable/read-only states

---

# 34. Forms

## ERP UI INTERPRETATION

Forms should be:

- organized
- clear
- logical
- readable
- minimally decorated

Group fields by business meaning.

Use clear hierarchy and predictable spacing.

Avoid creating one visually crowded form.

---

# 35. Dashboards

## ERP UI INTERPRETATION

Dashboards should communicate:

- control
- clarity
- confidence

Prefer:

- relevant KPIs
- clear charts
- limited palette
- obvious reporting period
- useful comparison
- drill-down

Avoid:

- decorative gauges
- 3D charts
- excessive colors
- flashy animations
- meaningless visualizations

---

# 36. Buttons and Actions

## ERP UI INTERPRETATION

Buttons must have a consistent hierarchy.

Use brand color deliberately.

Do not make every button red.

Primary business action may use Hadron Red where appropriate.

Secondary actions should remain neutral.

Destructive actions must remain clearly distinguishable.

---

# 37. Status Indicators

## ERP UI INTERPRETATION

Status indicators should be:

- compact
- readable
- consistent

Use light backgrounds rather than large saturated surfaces.

The same business status must always have the same visual treatment.

---

# 38. Shadows, Gradients and Decorative Effects

## ERP UI INTERPRETATION

The Brand Guideline emphasizes simplicity, control and avoidance of unnecessary decoration.

Therefore in ERP:

Avoid as a default:

- decorative gradients
- glassmorphism
- heavy shadows
- glowing effects
- unnecessary transparency
- dramatic elevation

Small shadows may be used where required to indicate temporary depth, such as:

- menus
- dialogs
- popovers

---

# 39. Corners

## ERP UI INTERPRETATION

Use moderate and controlled border radius.

Avoid excessive rounded, playful consumer-app styling.

Pill shapes should generally be limited to functional uses such as:

- status badges
- chips
- filters

---

# 40. Animation

## ERP UI INTERPRETATION

Animation should remain quiet and functional.

Suitable uses:

- loading
- menu transition
- modal transition
- state feedback

Avoid decorative motion.

---

# 41. Icons

## ERP UI INTERPRETATION

Use one consistent icon family.

Icons should feel:

- simple
- geometric
- technical
- familiar

Avoid mixing unrelated icon systems.

---

# 42. Error and Success Communication

## ERP UI INTERPRETATION

System communication should follow Hadron's official tone:

- calm
- transparent
- clear
- responsible

Errors should explain what happened and what the user can do.

Avoid dramatic or alarming wording unless the business situation is genuinely critical.

Success messages should be restrained and clear.

---

# 43. Accessibility

## ERP UI INTERPRETATION

Brand implementation must not reduce usability.

Ensure:

- readable contrast
- readable type size
- keyboard accessibility where appropriate
- color-independent status meaning

When accessibility requires adjusting a tint or UI treatment, preserve the brand identity while protecting readability.

---

# 44. Desktop and Tablet

## ERP UI INTERPRETATION

Primary target:

`Desktop`

Secondary target:

`Tablet`

Responsive behavior should be supported.

However, do not damage desktop productivity merely to force complex ERP grids into a consumer-style mobile layout.

Dedicated mobile workflows may be designed later where operationally justified.

---

# 45. PDF Reports

## ERP UI INTERPRETATION

Formal PDF reports should follow the Brand Guideline more strongly than everyday operational pages.

Use as appropriate:

- official logo
- approved colors
- approved typography
- generous margins
- clear hierarchy
- structured tables
- minimal decoration

Reports should remain highly readable in print.

---

# 46. Excel Exports

## ERP UI INTERPRETATION

Excel exports should primarily optimize data usability.

Use restrained branding.

Appropriate features may include:

- report title
- generation date
- frozen headers
- logical column widths
- typed cells
- subtle Hadron header treatment

Do not transform Excel exports into marketing documents.

# 51. Codex Brand Workflow

Before establishing the initial production design system:

1. Read this document.
2. Review the official PDF.
3. Inspect official supplied brand assets.
4. Confirm available official fonts.
5. Confirm available logo variants.
6. Create the initial design-token proposal.
7. Create only a small representative UI set.
8. Show the result to the project owner.
9. Wait for approval.
10. Only then propagate the design system across modules.

Do not create large numbers of pages before the visual language has been approved.

# 53. Final Rule

The official Hadron Brand Guideline is always the visual authority.

The ERP must translate that identity into software without changing its essence.

The desired visual result should reflect the official Hadron principles:

**Professional, precise, calm, controlled, modern, trustworthy, minimal and engineered.**

Where this document introduces rules that are not explicitly present in the official Brand Guideline, they must be treated as:

**ERP UI INTERPRETATION**

and must never override an official brand rule.
